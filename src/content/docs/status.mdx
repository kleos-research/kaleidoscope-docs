Kaleidoscope is installable and needs a key to run. Nothing is signed for
release, and there is no account to sign in to. That is the whole status, and
the rest of this page says what each part of it means.

## Is anything down?

No, and there is nothing that could be.

Kaleidoscope runs on your machine. The engine that stores and ranks your memory
is a local process; there is no server between you and it, no API endpoint, no
hosted memory, and no account service you depend on to read your own vault. A
status page for a local program has no uptime to report, and we would rather say
that than invent a green tick.

If a hosted service ever exists, its status will be published here, and this
section will say something other than "there is nothing that could be down."

## Can I install it?

Yes.

```bash
npm install -g @kleos-research/kaleidoscope
```

macOS and Linux, on Apple Silicon and x86_64. Windows is not supported yet.

You need a key to run it — email
[contact@kleosresearch.xyz](mailto:contact@kleosresearch.xyz). There is no
Python package you can use: `kscope-memory` is registered on PyPI, but only as a
0.0.0 placeholder that ships no working code and says as much in its own
summary, and `kaleidoscope-memory` was planned and never registered.

Nothing is signed for release, so what you install is unsigned software on your
machine. That is on the list to fix.

## Do I need an account?

No, and there is no way to make one. Your key is all that is needed, and your
vault has never depended on an account.

## Two contracts you can check right now

They are published as files, and they are the closest thing to a live interface
this project has today:

- [The two tools a model sees](/reference/kaleidoscope-mcp.json) — `search` and
  `remember`, and nothing else. No operator command is ever a model tool.
- [The full command-line help](/reference/kscope-cli.txt) — every command and
  flag of `kscope`, verbatim. It is the help text of the one program that
  installs: there is no second executable to install, so a command it does not
  name is one no download of ours gives you. It is a page about commands rather
  than a complete inventory of behaviour — `--no-wire`, for one, works and is
  not on it.

## What we have actually run

This is the part that is easy to overstate, so it is stated flatly.

**Machines.** Kaleidoscope has been run on one kind of machine: a Mac with Apple
Silicon. It is built and published for four — macOS on Apple Silicon and x86_64,
Linux on arm64 and x86_64 — so on any of them there is something to install. A
build existing for a platform is not the same as our having run it there, and on
the other three we have not, which is what this section is for. Windows on x86_64 has had a compiler check of the
memory engine's source and nothing more: nothing was assembled into a program for
it, nothing was linked, and nothing has been run there.
