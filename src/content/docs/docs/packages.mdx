```bash
npm install -g @kleos-research/kaleidoscope
```

That is the whole install. You need a key to run it — email
[contact@kleosresearch.xyz](mailto:contact@kleosresearch.xyz) and we will send
you one.

## What your machine needs

| | |
|---|---|
| Operating system | macOS or Linux |
| Architecture | arm64 (Apple Silicon) or x86_64 |
| Node.js | 18 or newer |

Windows is not supported yet. [Platforms](/docs/compatibility/) has the full
matrix.

## What lands on your disk

Two packages, both at version {release.release_version}.

| Package | Carries |
|---|---|
| `@kleos-research/kaleidoscope` | the `kscope` command, and the launcher that picks your platform's binary |
| one platform package, below | the memory engine as object code, with the setup work `kscope init` does compiled into it |

npm installs the platform package that matches your machine and skips the other
three.

There is no install hook, no download at install time, no compiler step and no
source build. Installing puts files on your disk and does nothing else.

## Licences

The memory engine is proprietary object code, and its source is not in the
package. Everything around it is Apache-2.0: the command-line tool, both SDKs,
every integration and the agent skill.

## Signing

Nothing is signed for release. There is no Apple signing and no notarisation,
and the native code is ad-hoc signed only. It is on the list to fix.

## There is no Python package

`kscope-memory` on PyPI is a 0.0.0 placeholder whose own summary says it is not
yet released. `kaleidoscope-memory` was planned and never registered — if you
find that name, it is not us.
