Kaleidoscope targets macOS on Apple Silicon and Intel, Linux on x86_64 and
arm64, and Windows on x86_64 and arm64.

**Four of those six are published today**, and `npm install -g
@kleos-research/kaleidoscope` brings down the one built for your machine. You
need a key to run it, and nothing is signed for release. Windows is the platform
on the list you cannot install on yet. [What is available today](/status/).

| platform | architectures | today |
|---|---|---|
| macOS | Apple Silicon, Intel | published on npm |
| Linux | x86_64, arm64 | published on npm |
| Windows | x86_64, arm64 | no package published |

## Windows creates no vault

On Windows, creating a new vault is refused on purpose. Windows needs its own
filesystem work first — file locking, link handling, and flushing writes all the
way to the disk — and until that lands Kaleidoscope stops rather than writing
memory it cannot stand behind.

This is a deliberate refusal in the code, not a gap, and it is the one platform
fact worth knowing before you plan around it. There is no Windows package
published for the install to bring down in the first place, and the rest of the
Windows work is outstanding too, so do not read the refusal as the only thing
between you and a working install there.

## What has actually been run

Kaleidoscope is built and published for four platforms — macOS on Apple Silicon
and x86_64, and Linux on arm64 and x86_64 — and you can install and run it on
any of them. We have run it ourselves on one: a Mac with Apple Silicon. Built
and published is not the same as tried by hand, and the difference is worth
knowing.
[The full account is on the status page](/status/).
