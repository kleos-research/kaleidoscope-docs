---
title: Diagnostics
description: Where your vault is, whether the engine is complete, and whether your key is working.
---

Four commands answer the questions you are likely to have when something looks
wrong. None of them reads or changes a single memory.

## Where is my memory?

```bash
kscope where
```

Prints the vault this directory resolves to, and the workspace it belongs to.
Run it when you are not sure which project's memory your agent is talking to.

## Is my key working?

```bash
kscope gate
```

Says whether this build checks a licence, which commands need one, and where it
looks for your key. If a command has been refused, this is the page that tells
you why in one line.

```bash
kscope activate
```

Re-checks the key you already have and stores it. `"entitled":true` means you
are set up.

## Is the engine complete?

```bash
kscope model
```

Should print `"status":"bundled"`. Anything else means the part that understands
what your memories mean is missing, and search will quietly get worse rather
than fail — which is why it is worth checking directly.

## Is my vault healthy?

```bash
kscope vault-verify /path/to/.kaleidoscope
```

Counts what is stored and reports whether the copies agree. It reads only.

For a deeper report, `kscope call doctor` runs the full diagnostic and returns
JSON. It is an operator command, so your agent is never offered it.
