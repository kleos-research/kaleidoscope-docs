`kscope` is the command. It creates a vault, wires your editor to it, and
answers questions about both.

```bash
npm install -g @kleos-research/kaleidoscope
kscope --help
```

[The full help text](/reference/kscope-cli.txt) is the authority on every
argument.

## The verbs

| To do this | Run | Page |
|---|---|---|
| Create a vault and wire your editor | `init` | [Connect an editor](/docs/cli/connect/) |
| Write the instruction file and skill | `init` | [Agent instructions](/docs/cli/instructions/) |
| Name a vault so an editor can start with it | `init-profile`, `profile create`, `profile import` | [Profiles and vaults](/docs/cli/profiles/) |
| See, inspect or forget a profile | `profile list`, `profile show`, `profile launch`, `profile remove` | [Profiles and vaults](/docs/cli/profiles/) |
| Find out which vault you are talking to | `where` | [Diagnostics](/docs/cli/diagnostics/) |
| Check the key, the model, the vault | `gate`, `activate`, `model`, `vault-verify` | [Diagnostics](/docs/cli/diagnostics/) |
| Run an engine for an agent | `mcp`, `serve`, `context`, `call` | [MCP reference](/docs/mcp/) |
| Migrate, preview or delete a vault | `vault-migrate`, `vault-preview`, `vault-delete` | [Operations](/docs/operations/) |
| Read the tool contract | `schema` | [MCP reference](/docs/mcp/) |
| Read the third-party notices | `licences` | — |

`kscope init` appears twice because one run does both jobs: it creates the
vault, then tells every agent on this machine that the vault exists.

## The flags

| Flag | On | Effect |
|---|---|---|
| `--profile NAME` | `mcp`, `serve`, `context`, `call` | Work in the vault that profile names. Nothing else accepts it. |
| `--no-wire` | `init` | Create the vault and write no editor configuration. Real, though `--help` does not list it. |
| `--root-only` | `where` | Print only the vault root and the project it came from. |
| `--cross-backend` | `vault-verify` | Widen the check. |
| `--help`, `-h` | any invocation | Print the command surface. |
| `--version`, `-V` | any invocation | Print the version. |

`kscope init` takes no `--profile`. It works on the directory you are in, or on
a root you name as a positional argument.

There is no `--engine`, no `--dry-run` and no `--yes`. An unknown verb prints
the help text; an unknown argument to `init` is refused by name, and nothing is
created.

## Where the wiring goes

| What | Where | Why |
|---|---|---|
| MCP server entry | your home directory | An agent runs your work in a worktree or a temporary clone, and an entry inside one project directory is never read from there. |
| Instruction file and skill | the project | Git carries them into that worktree or clone. |

## What init writes, and what it leaves alone

- Kaleidoscope writes only the block it owns, between ownership comments
  wherever the file format has room for them.
- Every file it writes gets a receipt beside it:
  `config.toml.kaleidoscope-owner.json` beside a host configuration,
  `CLAUDE.md.kaleidoscope-instruction-owner.json` beside an instruction file.
- A file it changes rather than creates is copied to
  `<name>.kaleidoscope-backup` first. The rest of the file is untouched.
- If what it finds no longer matches the receipt, it stops at that file and
  reports that step as failed. The other steps still run.
- The configuration it writes carries no token, no provider key and no vault
  location. It names this executable, a profile, and the tools `search` and
  `remember`.
- Running `kscope init` again is safe. An existing vault is left as it is and
  the wiring is re-checked.

## The second executable

Some verbs written about elsewhere — `connect`, `disconnect`, `config`,
`doctor`, `teardown`, `profile use`, `instructions install`, and the whole
account surface — belong to `kaleidoscope`, a second executable built from
source and published on no channel. Nothing on this site asks you to run one.
[Account commands](/docs/cli/account/) lists them.
