---
title: Connect an editor or agent
description: kscope init — creating a project's memory and wiring it into whichever editor or agent you use.
---

One command does both jobs. `kscope init`, run inside a project, creates that
project's memory and writes the entry your editor or agent needs to find it.

```bash
cd ~/your-project
kscope init
```

It tells you what it did, line by line: the vault it created, the `.gitignore`
rule it added, and then a step for each thing it wired — the memory server
registered with an agent, the instruction file written for it, and the skill
installed where that agent reads skills. It knows Claude Code, Codex, Cursor
and OpenCode, and it wires the ones whose configuration directory already exists
on this machine. If it recognises none of them it writes an `AGENTS.md` instead,
which most other agents will read, and says so.

Restart your editor afterwards. Until you do, it is still running with the
configuration it started with.

## The profile the entry names

The entry `kscope init` writes starts this executable with `--profile default`,
and creating the vault does not create that profile. Write it once, naming the
vault `init` just made:

```bash
kscope profile import default ~/your-project/.kaleidoscope
```

Until that profile exists, anything started with `--profile default` refuses
with `profile does not exist`, and the refusal is all your editor will show you.
[Profiles and vaults](/docs/cli/profiles/) has the rest of it.

## It will not overwrite your work

Kaleidoscope only touches the block it owns, and it leaves a receipt beside each
one. If it finds a Kaleidoscope entry that does not match its receipt — because
you edited it, or added one by hand — it stops, changes nothing, and tells you
which file to look at. That is the intended behaviour, not a failure: the
alternative is silently replacing something you wrote on purpose.

## Removing it

There is no `disconnect` on the command you have. The verb exists, but only in
`kaleidoscope`, the manager executable, which is built from source and published
on no channel — so removing the wiring is something you do by hand. Everything
`kscope init` writes is marked and receipted so that you can.

The memory server entry is in your home directory, one file per agent: the
`kaleidoscope` entry under `mcpServers` in `~/.claude.json`, in
`~/.cursor/mcp.json` and in `~/.config/opencode/opencode.json`, and the block
between the `kaleidoscope-manager` marker comments in `~/.codex/config.toml`.
Delete the entry or the marked block, and the `.kaleidoscope-owner.json` receipt
beside the file, which is the record of what was put there.

The instruction file and the skill are in the project: the marked block in
`CLAUDE.md` or `AGENTS.md`, `.claude/skills/use-kaleidoscope/` for Claude Code,
`.agents/skills/use-kaleidoscope/` for Codex and OpenCode, and
`.cursor/rules/kaleidoscope.mdc` for Cursor. Each of those has a receipt beside
it too. `npm uninstall -g @kleos-research/kaleidoscope` removes the command
itself, and nothing else.

None of that touches your memory, and none of it needs to: unwiring an editor is
not a way to delete a vault, and deleting a vault is not a way to unwire an
editor. An entry pointing at a vault that no longer exists is harmless, and
re-running `kscope init` writes the wiring back.

[Operations](/docs/operations/) covers moving a vault, backing it up, and
deleting one on purpose.
