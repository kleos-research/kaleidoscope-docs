---
title: Connect an editor or agent
description: kscope init — create a project's memory and wire it into Claude Code, Codex, Cursor or OpenCode.
---

`kscope init` creates the project's memory and writes the entry your editor
needs to find it. Run both commands:

```bash
cd ~/your-project
kscope init
```

The entry `init` writes starts the engine with `--profile default`, and creating
the vault does not create that profile. The second command writes it. Skip it
and your editor shows `profile does not exist` and nothing else.

Restart your editor. Until you do it is still running with the configuration it
started with.

## What you should see

```
kscope: created vault ~/your-project/.kaleidoscope (repository default)
kscope: wrote /.kaleidoscope/ to a new ~/your-project/.gitignore
kscope: wired codex, claude-code, cursor, opencode
kscope:   create the default profile, which the host entries name
kscope:   register the MCP server with codex
kscope:   agents for codex
kscope:   skill for codex
...
kscope: restart your agent, then ask it to search your memory.
```

One line per step, and a named failure for any step that could not be written.
`init` wires an agent only when that agent's configuration directory already
exists on this machine. If it finds none it writes an `AGENTS.md`, which most
other agents read, and says so.

## What lands where

| Agent | MCP entry | Instructions | Skill |
|---|---|---|---|
| Claude Code | `~/.claude.json` | a marked block in `CLAUDE.md` | `.claude/skills/use-kaleidoscope/` |
| Codex | `~/.codex/config.toml` | a marked block in `AGENTS.md` | `.agents/skills/use-kaleidoscope/` |
| Cursor | `~/.cursor/mcp.json` | `.cursor/rules/kaleidoscope.mdc` | none |
| OpenCode | `~/.config/opencode/opencode.json` | a marked block in `AGENTS.md` | `.agents/skills/use-kaleidoscope/` |

MCP entries go in your home directory; instructions and skills go in the
project, where git carries them into the worktree or clone your agent works in.

Each file gets a receipt beside it — `.kaleidoscope-owner.json` for a host
configuration, `.kaleidoscope-instruction-owner.json` for an instruction file or
skill. A file that already existed is copied to `<name>.kaleidoscope-backup`
first.

Nothing written carries a vault path, a provider key or an account credential.
The entry names this executable, a profile, and the two tools `search` and
`remember`.

## Running it again

`kscope init` again is safe. A root that is already a vault is reported and left
exactly as it is; the wiring is re-checked and repaired.

If a Kaleidoscope block no longer matches its receipt — you edited inside the
markers, or wrote an entry by hand — that step stops and names the file. The
other steps still run.

To create the vault and write no editor configuration at all:

```bash
kscope init --no-wire
```

## Removing it

There is no `disconnect` verb on `kscope`, so remove the wiring by hand. Delete
each of these with the receipt beside it:

- the `kaleidoscope` entry under `mcpServers` in `~/.claude.json`,
  `~/.cursor/mcp.json` and `~/.config/opencode/opencode.json`
- the block between the `kaleidoscope-manager` markers in `~/.codex/config.toml`
- the marked block in `CLAUDE.md` or `AGENTS.md`
- `.claude/skills/use-kaleidoscope/`, `.agents/skills/use-kaleidoscope/` and
  `.cursor/rules/kaleidoscope.mdc`

`npm uninstall -g @kleos-research/kaleidoscope` removes the command itself.

None of that touches your memory. An entry pointing at a vault that no longer
exists is harmless, and `kscope init` writes the wiring back.
[Operations](/docs/operations/) covers moving, backing up and deleting a vault.
