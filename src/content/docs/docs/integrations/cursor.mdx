Install and activate first — [Getting started](/docs/getting-started/) covers both. Without a
key the wiring below succeeds and the server refuses with `E_NO_KEY` the moment your editor
starts it.

`kscope init` wires Cursor when `~/.cursor` exists. Cursor gets a rule file and
no skill.

## Wire it

```bash
cd ~/your-project
kscope init
```

Run both, in that order. Skip the import and Cursor reports
`profile does not exist`.

Restart Cursor, then ask it to search your memory.

## What init writes

| What | Where |
|---|---|
| MCP entry | `~/.cursor/mcp.json`, under `mcpServers` as `kaleidoscope` |
| Instructions | `.cursor/rules/kaleidoscope.mdc` |
| Skill | none |
| Receipt | `~/.cursor/mcp.json.kaleidoscope-owner.json`, and `.cursor/rules/kaleidoscope.mdc.kaleidoscope-instruction-owner.json` |
| Backup | `~/.cursor/mcp.json.kaleidoscope-backup`, when the file was already there |

```json
{
  "mcpServers": {
    "kaleidoscope": {
      "command": "/absolute/path/to/kscope",
      "args": ["mcp", "--profile", "default"]
    }
  }
}
```

Cursor's entry carries no `type` field.

## The rule instead of a skill

Cursor has no skill directory, so the rule file carries the instructions. Its
frontmatter sets `alwaysApply: true`, and Cursor reads it every turn.

```yaml
---
description: Apply Kaleidoscope memory policy safely
alwaysApply: true
---
```

If Cursor lists the tools but never calls them, check that file first.
[Give your agent the skill](/docs/skill/) has the text it should hold.

## Check it

```bash
kscope profile list
kscope profile launch default
```

`launch` prints the command, the arguments and the tool list — `search` and
`remember` — that the entry in `~/.cursor/mcp.json` should match.

## Remove it

Delete each of these, and the receipt beside it:

- the `kaleidoscope` entry under `mcpServers` in `~/.cursor/mcp.json`
- `.cursor/rules/kaleidoscope.mdc`

Either one can go without the other. Your memory stays.
[Connect an editor or agent](/docs/cli/connect/) covers every editor at once.
