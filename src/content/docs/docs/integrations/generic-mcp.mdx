---
title: Any other MCP client
description: Get Kaleidoscope's launch descriptor with kscope profile launch and run it as one long-lived stdio MCP server.
---

Any standard MCP client runs Kaleidoscope from the descriptor the engine prints.
You do not hand-write the command.

## Get the descriptor

```bash
cd ~/your-project
kscope init --no-wire
kscope profile import default ~/your-project/.kaleidoscope
kscope profile launch default
```

`--no-wire` creates the vault and leaves every editor configuration alone. Drop
it to wire Claude Code, Codex, Cursor and OpenCode as well.

The last command prints this:

```json
{
  "version": 1,
  "transport": "stdio",
  "command": "/absolute/path/to/kscope",
  "args": ["mcp", "--profile", "default"],
  "tools": ["search", "remember"],
  "environment": {}
}
```

| Field | What to do with it |
|---|---|
| `command`, `args` | the server definition in your own configuration |
| `transport` | stdio, one long-lived process |
| `tools` | the whole model-facing surface; allow exactly these two |
| `environment` | empty — pass no vault path, key or token |

## Wire it in

Put `command` and `args` into your client's server definition. Start the server
once and reuse the session, rather than one process per tool call.

## Check it

Your client's tool list should hold exactly `search` and `remember`. If
`kscope profile launch default` prints `profile does not exist`, run the
`profile import` above.

## Remove it

Delete the server definition from your own configuration. This route writes
nothing else.
