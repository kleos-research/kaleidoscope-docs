Every page here assumes `kscope` is installed and activated —
[Getting started](/docs/getting-started/) covers both.

Everything on this page reaches one engine on your machine and sees the same two
tools, `search` and `remember`.

## Editors

```bash
cd ~/your-project
kscope init
kscope profile import default ~/your-project/.kaleidoscope
```

Restart the editor, then ask it to search your memory.

`kscope init` wires every editor whose configuration directory already exists.
`kscope init --no-wire` creates the vault and writes no editor configuration.

| Editor | MCP entry | Instructions | Skill |
|---|---|---|---|
| [Claude Code](/docs/integrations/claude-code/) | `~/.claude.json` | `CLAUDE.md` | `.claude/skills/use-kaleidoscope/` |
| [Codex](/docs/integrations/codex/) | `~/.codex/config.toml` | `AGENTS.md` | `.agents/skills/use-kaleidoscope/` |
| [Cursor](/docs/integrations/cursor/) | `~/.cursor/mcp.json` | `.cursor/rules/kaleidoscope.mdc` | none |
| [OpenCode](/docs/integrations/opencode/) | `~/.config/opencode/opencode.json` | `AGENTS.md` | `.agents/skills/use-kaleidoscope/` |

Cursor gets a rule file and no skill.

## Before any of it

`npm install -g @kleos-research/kaleidoscope` gives you `kscope`, and running it
needs a key. [Install](/docs/packages/) covers both steps.
[Give your agent the skill](/docs/skill/) is the file that tells an agent when to
read its memory and when to write to it.
