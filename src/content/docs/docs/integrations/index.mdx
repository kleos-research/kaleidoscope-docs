---
title: Editors, agents and frameworks
description: The one command that wires each editor or agent to your local Kaleidoscope vault, and what every one of them sees.
---

Every editor and agent below talks to the same engine on your machine, over one
long-lived process, and sees exactly two tools: `search` and `remember`. Connect
five of them and they share one memory instead of starting five stores.

One command wires the editors. `kscope init`, run inside a project, creates that
project's vault and then wires every agent whose own configuration
directory already exists on this machine. What it writes is different for each
one — a different configuration file, a different instruction file, a different
place a skill lives — and that difference is what the pages below set out.

| | wired by |
|---|---|
| [Claude Code](/docs/integrations/claude-code/) | `kscope init`, in the project |
| [Codex](/docs/integrations/codex/) | `kscope init`, in the project |

Frameworks connect through their own MCP adapter, using the same descriptor:
[Claude Agent SDK](/docs/integrations/claude-agent-sdk/) ·
[OpenAI Agents SDK](/docs/integrations/openai-agents-sdk/) ·
[LangChain](/docs/integrations/langchain/) ·
[LangGraph](/docs/integrations/langgraph/) ·
[CrewAI](/docs/integrations/crewai/)

The build these pages describe is the one that is published:
`npm install -g @kleos-research/kaleidoscope` gives you `kscope` today, and
running it needs a key. [Install](/docs/packages/) covers both steps.
[What has actually been run, and on what](/status/).

`kscope init` also installs the skill that tells your agent when to read its
memory and when to write to it — for Cursor, a project rule instead. What that
document says, and how to install it by hand, is on
[give your agent the skill](/docs/skill/).
