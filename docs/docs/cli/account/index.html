Early access Kaleidoscope needs a key to run. Email contact@kleosresearch.xyz and we will send you one.

Account commands

None of the commands on this page ships. Every one of them belongs to kaleidoscope, the manager executable, which is built from source and published on no channel — so they are not commands that fail for you, they are commands you cannot obtain. Even built from source they would go no further: each one that reaches the account service answers provider not configured, because no sign-in service is configured or published either.

They are written down here so you can see the shape of what signing in will and will not do when it arrives.

What there is instead

Section titled “What there is instead”

The alpha is opened by a key, not by an account. Email contact@kleosresearch.xyz for one, and then:

activate takes the key from KALEIDOSCOPE_API_KEY, from the key file, or from standard input; stores it at the path kscope gate reports, so an engine your editor starts with an empty environment still finds it; and waits for the verdict rather than leaving the next command to discover an empty cache. It is the whole of the account-shaped surface on the executable you installed.

You do not need an account to use Kaleidoscope. Your memory lives on your machine and has never needed one.

The surface, when it arrives

Section titled “The surface, when it arrives”

Everything from here down is kaleidoscope, not kscope. None of it runs on the command you have.

Sign in and out

Section titled “Sign in and out”

login is an ordinary browser sign-in; --device is the code-based path for a machine with no browser.

logout removes or revokes your credentials according to the scope you chose. --all-devices ends every session on the account; --local-only removes the credential from this machine and warns you that it has not revoked anything remotely. Neither changes which profile a command resolves to, and neither alters a byte of your vault.

kaleidoscope status reports your account session on this machine. It is not related to the status page, which is about what is available.

Linked sign-in providers

Section titled “Linked sign-in providers”

account identities is where you get the opaque UUID that account unlink needs; it lists those IDs and nothing else.

account revoke-session has the deliberately narrow meaning of revoking the session you are currently using. It does not deactivate an account.

Devices

Section titled “Devices”

The devices attached to your account, and how to detach one. Revoking a device is an account operation; the vault on that device is untouched.

Local account reference

Section titled “Local account reference”

These three would work offline, because they never leave your machine: they write a non-secret account ID into a local profile and nothing more — no engine started, no service contacted, no vault touched, no credential stored. They are still manager commands, so they are still not commands you can run.

The boundary

Section titled “The boundary”

On the executable that ships there is no boundary to police, because there is no account traffic: kscope carries no account commands at all, and activate speaks only about your key.

In the manager, account traffic goes to a closed list of account-only routes and never touches the memory engine. A guard rejects memory fields, profile fields and absolute local paths before anything is sent.

What signing in would mean, and where a credential would be kept: Account and devices.
